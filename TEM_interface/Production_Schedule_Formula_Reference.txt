SECTION 1 — COLUMN STRUCTURE (Year Mapping)
================================================================================

Columns map to model years as follows:
  Col A  = Hard-input rate for the row (e.g. 0.77 for Partings, 0.05 for CHP Rehandling)
  Col B  = Row description / label

  Col E  = Year -4  (Pre-production year 1 of 4)

  Col G  = Year -2  (Pre-production year 3 of 4)
  Col H  = Year -1  (Pre-production year 4 of 4)
  Col I  = Year  1  (first production year)
  Col J  = Year  2
  Col K  = Year  3
  Col L  = Year  4
  Col M  = Year  5
  Col N  = Year  6
  Col O  = Year  7
  Col P  = Year  8
  Col Q  = Year  9

  Col T  = Year 12
  Col U  = Year 13
  Col V  = Year 14
  Col W  = Year 15
  Col X  = Year 16
  Col Y  = Year 17
  Col Z  = Year 18
  Col AA = Year 19

Year numbering (row 3) uses the formula:
  = IF(col2 = 0, 0,
      IF((col2 - Assumptions_Dashboard!D7) < 0,
         col2 - Assumptions_Dashboard!D7,
         col2 - (Assumptions_Dashboard!D7 - 1)))
  where D7 = Production Starting Year = 5 (i.e., column 9 = Year 1, column 5 = Year -4)

SECTION 2 — HEADER / CONTROL ROWS (Rows 1–4)
================================================================================

ROW 1: Calendar Year Header
  Formula pattern (Col F onward): = PrevCol + 366
  Col E (start): = Assumptions_Dashboard!$D$5   [= Effective Start Date = 2026-01-01]
  Purpose: Shows the calendar year of each column for display only.

ROW 2: Absolute Year Counter (1, 2, 3, … 23)
  Col E: = 1  (hard-coded start)
  Formula pattern: = IF(MAX($E$2:PrevCol) <= (Assumptions_Dashboard!$D$11 + Assumptions_Dashboard!$D$6 - 2),
                       PrevCol + 1, 0)
  Purpose: Determines how many columns of data exist. Stops incrementing when
           Life of Mine + pre-production years are exhausted.
  Key inputs:
    Assumptions_Dashboard!D11 = Pre-production period length
    Assumptions_Dashboard!D6  = Production start year (calendar)

ROW 3: Signed Project Year (-4, -3, -2, -1, 1, 2, ... 19)
  DERIVED from ROW 2 using:
  = IF(col2 = 0, 0,
      IF((col2 - Assumptions_Dashboard!$D$7) < 0,
         col2 - Assumptions_Dashboard!$D$7,
         col2 - (Assumptions_Dashboard!$D$7 - 1)))
  Key input: Assumptions_Dashboard!D7 = Production Starting Year = 5
  Purpose: Converts absolute year number to signed project year for reporting.

ROW 4: Total Available Hours for Excavation
  Unit: hrs
  LOM Total (D4): = MAX(E4:AD4) → 7,920 hrs/year
  Year formula:   = IF(col3 <= 0, 0, Assumptions_Dashboard!$D$29)
  [= Zero for pre-production years; uses D29 = 7,920 for all production years]
  Key input: Assumptions_Dashboard!D29 = Total Available Hours / Year = 7,920 hrs
  Meaning: Annual excavation hours available — 0 pre-production, 7,920 in operation.

SECTION 8 — REHANDLING COST (Row 35)
================================================================================

────────────────────────────────────────────────────────────────────────────────
ROW 35: Rehandling Cost
────────────────────────────────────────────────────────────────────────────────
  Unit: INR Cr
  LOM Total (D35): = SUM(E35:AH35)  → 529.48 INR Cr
  FORMULA (each year): = Assumptions_Dashboard!$D$153 * col13 / 10
                       = MDO Rehandling Rate (INR/bcm) × Waste_Rehandle(Mbcm) / 10
  Example — Year 7:  = 70 × 11.85 / 10  = 82.95 INR Cr
  Example — Year 11: = 70 ×  7.06 / 10  = 49.42 INR Cr
  Pre-production & Years 1–6 and 15–19: = 0 (no rehandling in those years)

  Key input: Assumptions_Dashboard!D153 = 70  (MDO Rehandling Rate, INR/bcm)
             This is a HARD INPUT on the Assumptions Dashboard.

  Inter-sheet links from Rehandling Cost (Row 35):
    → Owner OPEX sheet uses Contractor OPEX!E18, which reads from this rehandling
      schedule to compute owner rehandling OPEX costs.
    → Contractor OPEX sheet also uses Row 13 (Waste - Rehandle) and Row 35 values.

  Note on confusion: The Production Schedule distinguishes between:
    (a) Rehandling at CHP (Row 12)  — small volume (~0.44 Mbcm/yr at steady state)
        relating to coal rehandling at the plant for loading/processing.
    (b) Waste - Rehandle (Row 13)   — large volume (7–12 Mbcm) in Years 7–14,
        relating to previously deposited OB/IB that must be moved again.
    Both appear in OPEX calculations but via different pathways.

SECTION 9 — REFERENCE TABLE (Rows 40–61): Diluted / Rounded / Cumulative
================================================================================

This section is a summary table showing coal production by year in a condensed
format, and is NOT used directly in calculations (it is a display section).

Row 40 headers: Diluted | Rounded | Cumulative
Row 41 sub-headers: Year | Coal (Mt) | GCV Dil (Kcal/Kg) | GCV Dil (Kcal/Kg) | Coal (Mt) | Waste (Mcum)
Rows 42–60: One row per production year (Years 1–19)

  Column K = Coal (Mt)  — Hard input values matching Row 5
  Column L = GCV Diluted (Kcal/Kg) — Hard input values matching Row 14
  Column M = GCV Rounded = ROUND(L42, -1)  [rounded to nearest 10]
  Column N = Cumulative Coal (Mt) = N_prev + K_current   [running total]
  Column O = Waste (Mcum) — Hard input values (same data as Row 8)

Row 61 (Total row):
  K61 = SUM(K42:K60)  = Total coal production (LOM)
  L61 = SUMPRODUCT(K42:K60, L42:L60) / SUM(K42:K60)  = Production-weighted avg GCV
  M61 = ROUND(SUMPRODUCT(K42:K60, M42:M60) / SUM(K42:K60), -1)  = Rounded LOM avg GCV
  O61 = SUM(O42:O60)  = Total LOM waste (Mcum)


================================================================================
SECTION 10 — INTER-SHEET RELATIONSHIPS FROM PRODUCTION SCHEDULE
================================================================================

The Production Schedule sheet is a PRIMARY DATA PROVIDER. Many downstream
calculation sheets pull data from it directly.

FROM Production Schedule → TO Government Sheet:
  Government!E2  ← 'Production Schedule'!E1   [Year label / calendar year]
  Government!E3  ← 'Production Schedule'!E3   [Project year number (signed)]
  Government!E4  ← 'Production Schedule'!E5   [Coal production (Mt)]

FROM Production Schedule → TO Owner OPEX Sheet (via Contractor OPEX):
  Owner OPEX    reads Contractor OPEX row 18 (Rehandling),
                which derives from Production Schedule rows 13 and 35.

FROM Production Schedule → TO Assumptions_Dashboard (derived values):
  Assumptions_Dashboard!D10 = =MAX('Production Schedule'!E5:AM5)
  [Rated Capacity = max annual production from schedule]

  Assumptions_Dashboard!D12 = =MAX('Production Schedule'!E3:AM3)
  [Life of Mine = max project year from schedule]

FROM Production Schedule → TO Contractor OPEX Sheet:
  Contractor OPEX reads from Production Schedule:
    Row 5  (Production Coal/Ore, Mt)   for MDO Coal cost calculation
    Row 8  (Total Waste, Mbcm)         for MDO OB/Topsoil cost calculation
    Row 9  (Topsoil, Mbcm)             for MDO Topsoil cost calculation
    Row 13 (Waste Rehandle, Mbcm)      for MDO Rehandling cost calculation

FROM Production Schedule → TO Fleet Sheet (Equipment sizing):
  Fleet reads production and waste volumes to size equipment fleet.

FROM Production Schedule → TO Productivity Sheet:
  Productivity uses Production (Row 5) and Waste (Row 8) to size equipment
  cycle times, and references Haul Distances (Rows 23–27).

SECTION 13 — NOTABLE FORMULA ERRORS / IMPROVEMENTS NEEDED IN BACKEND
================================================================================

The following are mismatches or gaps identified between the current backend
(calculate_tem.py) and the actual Excel Production Schedule formulas:

1. PARTINGS CALCULATION (Row 11):
   CURRENT BACKEND: Not computed at all — Partings is not stored as a separate
   schedule in MongoDB.
   EXCEL FORMULA: Partings = Total Waste × 0.77  (Row 11 = Row 8 × A11)
   FIX NEEDED: Store Partings in MongoDB as a separate schedule with formula:
               partings[year] = waste[year] × 0.77

2. REHANDLING AT CHP (Row 12):
   CURRENT BACKEND: Not computed — CHP rehandling volume is not stored.
   EXCEL FORMULA: CHP_rehandling = (Production / Rated_Capacity) × 0.05
                  = (Row5 / Assumptions_Dashboard.D32) × A12
   FIX NEEDED: Add CHP rehandling volume to MongoDB production_schedule collection.

3. OB CALCULATION (Row 10):
   CURRENT BACKEND: Uses "Waste (Topsoil + Overburden + Interburden)" as the
   combined waste number for MDO OB cost.
   EXCEL FORMULA: OB = Total_Waste - Topsoil - Partings
                     = Row8 - Row9 - Row11
   FIX NEEDED: MDO OB cost should use OB only (not total waste including partings),
               or the total waste number must be reconciled with the formula.

4. REHANDLING COST (Row 35):
   CURRENT BACKEND: MDO Rehandling = waste_rehandle × mdo_rehandle_rate / 10
                    where waste_rehandle comes from MongoDB
   EXCEL FORMULA: Rehandling_Cost = D153 × Row13 / 10  ✓ (This matches!)
   STATUS: Correct — only check that Row 13 values in MongoDB match the Excel.

5. BLASTED vs SURFACE MINER COAL (Rows 6–7):
   CURRENT BACKEND: Does not distinguish between blasted and surface miner coal.
   EXCEL FORMULA: Uses IF(D80 >= year, production, production × 0.15)
   IMPACT: This affects Explosives OPEX (only blasted coal needs explosives).
   FIX NEEDED: Explosive cost should be based on Row 6 (Blasted Coal), not Row 5.

6. WASTE REHANDLE YEARS:
   CURRENT BACKEND: Uses the "waste_rehandling" schedule from MongoDB.
   EXCEL VALUES: Only Years 7–14 have non-zero values (11.85 and 7.06 Mbcm).
   CHECK: Verify MongoDB production_schedule "Waste - Rehandle" document matches
          these values for each year.

7. STRIPPING RATIO:
   CURRENT BACKEND: Not used in calculations.
   EXCEL: Used in Fleet and Productivity sheets for equipment sizing.
   STATUS: No immediate action needed for financial model.
